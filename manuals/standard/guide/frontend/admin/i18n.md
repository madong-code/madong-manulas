# 3.1.9 国际化

基于 **vue-i18n**，内置 `zh-CN`（简体中文）与 `en-US`（英文）。

## 一、语言包分布

语言包分三处，由 `src/locales/loader/` 统一扫描、合并后注入 vue-i18n：

```
src/
├── lang/                        # 框架语言包（业务模块）
│   ├── zh-CN/
│   │   ├── system/
│   │   ├── member/
│   │   ├── content/
│   │   ├── app/
│   │   ├── ops/
│   │   ├── devtools/
│   │   ├── web/
│   │   ├── plugin/
│   │   └── components/
│   └── en-US/  （同结构）
├── locales/
│   ├── index.ts                 # 入口，导出 $t
│   ├── langs/                   # 应用语言包
│   │   ├── zh-CN/
│   │   │   ├── common.json
│   │   │   ├── page.json
│   │   │   └── demos.json
│   │   └── en-US/
│   └── loader/                  # 加载器
└── plugin/
    └── <插件名>/lang/            # 插件语言包
        ├── zh-CN/
        └── en-US/
```

## 二、Key 生成规则

**文件名即命名空间前缀**，这是最关键的规则。

| 目录 | Key 格式 | 示例 |
| --- | --- | --- |
| `locales/langs/` | `文件名.层级key` | `$t('page.auth.login')` |
| `lang/` | `文件名.层级key` | `$t('common.button.confirm')` |
| `plugin/*/lang/` | `插件名.文件名.层级key` | `$t('test.demo.greeting')` |

### 应用语言包 `locales/langs/`

```jsonc
// locales/langs/zh-CN/page.json
{
  "auth": { "login": "登录" },
  "dashboard": { "title": "概览" }
}
```

```ts
$t('page.auth.login')   // → 登录
```

> **不支持子目录**，文件必须直接放在语言目录下。

### 框架语言包 `lang/`

```jsonc
// lang/zh-CN/common.json
{
  "button": { "confirm": "确认" },
  "message": { "success": "操作成功" }
}
```

```ts
$t('common.button.confirm')   // → 确认
```

文件名中的 `.` 会创建嵌套层级：`lang/zh-CN/test.ss.json` → `$t('test.ss.*')`。

### 插件语言包 `plugin/*/lang/`

```jsonc
// plugin/test/lang/zh-CN/demo.json
{
  "greeting": "你好！欢迎使用插件语言包测试",
  "menu": { "home": "首页" }
}
```

```ts
$t('test.demo.greeting')
```

**自动扫描，无需修改 loader 代码。**

## 三、加载顺序与覆盖

```
1. locales/langs/     应用语言包
2. lang/              框架语言包
3. plugin/*/lang/     插件语言包
```

**后加载的同名 key 会覆盖先加载的**，因此插件可以覆盖框架文案。

## 四、语言目录映射

用户浏览器语言会被归一化：

| 输入 | 映射到 |
| --- | --- |
| `zh` / `zh-CN` / `zh_CN` / `zh-Hans` | `zh-CN` |
| `en` / `en-US` / `en_US` / `en-GB` | `en-US` |

## 五、使用方式

### 模板中

```vue
<template>
  <ElButton>{{ $t('common.button.confirm') }}</ElButton>
</template>
```

### 脚本中

```ts
import { $t } from '#/locales';

ElMessage.success($t('common.message.success'));
```

### Schema 配置中

CRUD 配置里的所有文案都可国际化：

```tsx
import { $t } from '#/locales';

export const useCrudSchema = (): CrudSchema => ({
  crudApi: { /* ... */ },

  columns: [
    { field: 'name', title: $t('system.post.name') },
    { field: 'code', title: $t('system.post.code') },
  ],

  searchForm: {
    schema: [
      {
        component: 'Input',
        fieldName: 'LIKE_name',
        label: $t('system.post.name'),
      },
    ],
  },

  formDialog: {
    title: $t('system.post.title'),
    schema: [
      {
        label: $t('system.post.name'),
        fieldName: 'name',
        component: 'Input',
        rules: 'required',
      },
    ],
  },
});
```

> 注意 `useCrudSchema` 是**函数**，每次调用时才求值，因此切换语言后重新渲染即可生效。

### 带参数

```jsonc
{ "welcome": "欢迎，{name}！" }
```

```ts
$t('page.welcome', { name: 'admin' })
```

内置校验规则就是这样实现的：

```ts
return $t('ui.formRules.required', [ctx.label]);
```

## 六、新增语言文案

### 给业务模块加文案

1. 编辑 `src/lang/zh-CN/system/post.json`：

```json
{
  "title": "岗位管理",
  "name": "岗位名称",
  "code": "岗位编码"
}
```

2. 同步补 `src/lang/en-US/system/post.json`
3. 使用 `$t('post.title')`（文件名 `post` 作为前缀）

### 给插件加文案

1. 创建 `src/plugin/<插件名>/lang/zh-CN/` 和 `en-US/`
2. 添加 JSON 文件
3. 使用 `$t('<插件名>.<文件名>.<key>')`

无需注册，自动扫描。

## 七、后端文案国际化

请求层会自动把当前语言带给后端：

```ts
config.headers['Accept-Language'] = preferences.app.locale;
```

后端据此返回对应语言的提示信息，详见 [4.1.7 国际化](../../backend/getting-started/i18n.md)。

> 因此**接口返回的 `msg` 无需前端翻译**。

## 八、新增一门语言

1. 在 `src/lang/` 与 `src/locales/langs/` 下新建语言目录（如 `ja-JP`）
2. 复制 `zh-CN` 的文件结构并翻译
3. 在 loader 的语言映射中补充该语言
4. 补充 Element Plus、dayjs 的对应语言包（`src/locales/index.ts` 中扩展）

## 九、最佳实践

1. **不要硬编码中文** —— 所有面向用户的文案走 `$t()`。
2. **两种语言同步维护** —— 缺失的 key 会直接显示 key 本身，很显眼。
3. **按模块拆文件** —— 不要把所有文案堆在一个 JSON 里。
4. **Schema 用函数包裹** —— `useCrudSchema()` 保持为函数，确保语言切换后重新求值。
5. **插件文案放插件内** —— 保持插件自包含，便于装卸。
