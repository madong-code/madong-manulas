# 国际化

MDAdmin 使用 **Vue I18n**，并实现了一套**基于文件路径自动生成 key** 的语言包加载器。

---

## 二、三种 key 生成模式

加载器 `src/locales/loader/index.ts` 支持三种路径模式，**自动根据文件路径生成 i18n key**，无需手动维护索引。

### 2.1 模式一：`lang/` 目录模式

**规则**：`lang/<locale>/<目录…>/<文件名>.json` → key 为 `目录… + 文件名（点号拆分）`

| 文件路径 | 生成的 key 前缀 |
| --- | --- |
| `lang/zh-CN/system.json` | `system` |
| `lang/zh-CN/member/tag.json` | `member.tag` |
| `lang/zh-CN/member/tag.auth.json` | `member.tag.auth` |
| `lang/zh-CN/member/tag.user-tag.json` | `member.tag.user-tag` |
| `lang/zh-CN/content/message/notify.json` | `content.message.notify` |
| `lang/zh-CN/components/crud.json` | `components.crud` |

> 📌 **文件名中的点号也参与 key 层级**：`tag.auth.json` → `member.tag.auth`。

**示例**：

`lang/zh-CN/member/tag.json`

```json
{
  "title": "会员标签",
  "table": {
    "columns": { "name": "标签名称" }
  }
}
```

使用：

```ts
$t('member.tag.title')                      // 会员标签
$t('member.tag.table.columns.name')         // 标签名称
```

### 2.2 模式二：`locales/langs/` root 模式

**规则**：

- **根目录下的文件** → 文件名点号拆分后**直接作为 key**（不带目录前缀）
- **子目录下的文件** → 与模式一相同

| 文件路径 | 生成的 key 前缀 |
| --- | --- |
| `locales/langs/zh-CN/common.json` | `common` |
| `locales/langs/zh-CN/page.json` | `page` |
| `locales/langs/zh-CN/ui.form.json` | `ui.form` |
| `locales/langs/zh-CN/sub/x.json` | `sub.x` |

```ts
$t('common.confirm')
$t('page.dashboard.title')
```

### 2.3 模式三：插件命名空间模式

**规则**：`plugin/<插件名>/lang/<locale>/<目录…>/<文件>.json` → key 以**插件名开头**

| 文件路径 | 生成的 key 前缀 |
| --- | --- |
| `plugin/codegen/lang/zh-CN/index.json` | `codegen.index` |
| `plugin/codegen/lang/zh-CN/table.json` | `codegen.table` |
| `plugin/demo/lang/zh-CN/user/list.json` | `demo.user.list` |

插件语言包**自动带命名空间**，天然避免与主应用冲突。

## 三、加载与合并顺序

```ts
export function loadAllLocaleMessages(lang: SupportedLanguagesType): LocaleMessages {
  const localeDir = normalizeLocaleDir(lang);
  const messages: LocaleMessages = {};

  deepMerge(messages, loadLocalesLangs(localeDir));    // ① locales/langs/
  deepMerge(messages, loadAppLangLocales(localeDir));  // ② lang/
  deepMerge(messages, loadPluginLocales(localeDir));   // ③ plugin/*/lang/

  return messages;
}
```

**优先级（后者覆盖前者）**：

```
locales/langs/  <  lang/  <  plugin/*/lang/
   通用             业务          插件
```

合并采用 `deepMerge` **深度合并**，同层级不同 key 不会互相覆盖。

## 四、语言目录归一化

加载器支持多种语言标识写法，自动映射到实际目录：

```ts
const LOCALE_DIR_MAP: Record<string, string> = {
  en: 'en-US',
  'en-GB': 'en-US',
  'en-US': 'en-US',
  en_US: 'en-US',
  zh: 'zh-CN',
  'zh-CN': 'zh-CN',
  zh_CN: 'zh-CN',
  'zh-Hans': 'zh-CN',
};
```

| 传入 | 实际加载目录 |
| --- | --- |
| `zh`、`zh-CN`、`zh_CN`、`zh-Hans` | `zh-CN` |
| `en`、`en-US`、`en_US`、`en-GB` | `en-US` |

新增语言时需在此表中登记。

## 五、Key 冲突检测

当两个不同路径生成相同 key 且值不是对象时，会输出警告：

```ts
console.warn(
  `[i18n] Key conflict detected: "${keyPath}" is being overwritten. ` +
  `This may be caused by both directory-based file and dotted-filename file producing the same key.`,
);
```

**典型冲突场景**：

```
lang/zh-CN/member/tag.json        → member.tag
lang/zh-CN/member.tag.json        → member.tag   ⚠️ 冲突
```

> 警告最多输出 10 次（`conflictWarnCount < 10`），避免刷屏。

**避免方式**：同一模块的语言包**只用一种组织方式**，不要混用目录嵌套与点号文件名。

## 六、使用方式

### 6.1 在 `<script setup>` 中

```ts
import { $t } from '#/locales';

const title = $t('member.tag.title');
```

### 6.2 在模板中

```vue
<template>
  <div>{{ $t('member.tag.title') }}</div>
</template>
```

### 6.3 在 Schema 中

```tsx
import { $t } from '#/locales';

export const useCrudSchema = (): CrudSchema => ({
  columns: [
    {
      field: 'name',
      title: $t('member.tag.table.columns.name'),
    },
  ],
  formDialog: {
    title: $t('member.tag.title'),
    schema: [
      { fieldName: 'name', label: $t('member.tag.form.name'), component: 'Input' },
    ],
  },
});
```

### 6.4 带参数

```json
{ "welcome": "欢迎，{name}！", "total": "共 {count} 条" }
```

```ts
$t('page.welcome', { name: '张三' });
$t('page.total', { count: 100 });
```

### 6.5 数组参数

框架内置规则使用数组形式：

```ts
$t('ui.formRules.required', [ctx.label]);       // "xxx 不能为空"
$t('ui.placeholder.input');                      // "请输入"
$t('ui.placeholder.select');                     // "请选择"
```

## 七、新增语言包

### 7.1 为新业务模块添加

```
① 创建 src/lang/zh-CN/goods/category.json
② 创建 src/lang/en-US/goods/category.json（结构必须对称）
③ 直接使用 $t('goods.category.xxx')
```

`src/lang/zh-CN/goods/category.json`：

```json
{
  "title": "商品分类",
  "table": {
    "columns": {
      "name": "分类名称",
      "sort": "排序",
      "enabled": "状态"
    },
    "search": {
      "name": "分类名称"
    }
  },
  "form": {
    "name": "分类名称",
    "sort": "排序"
  }
}
```

**无需注册**，加载器自动扫描。

### 7.2 为插件添加

```
plugin/myplugin/lang/zh-CN/index.json    → myplugin.index.*
plugin/myplugin/lang/en-US/index.json
```

### 7.3 新增一种语言

```
① 创建 src/lang/<locale>/、src/locales/langs/<locale>/
② 在 LOCALE_DIR_MAP 中登记映射
③ 在语言切换组件中添加选项
```

## 八、命名规范

### 8.1 Key 层级建议

```json
{
  "title": "模块标题",
  "table": {
    "columns": { "字段名": "列标题" },
    "search":  { "字段名": "搜索项标签" }
  },
  "form": { "字段名": "表单标签" },
  "dialog": { "add": "新增", "edit": "编辑" },
  "message": { "deleteConfirm": "确认删除？" },
  "status": { "enabled": "启用", "disabled": "禁用" }
}
```

### 8.2 文件组织建议

| 场景 | 组织方式 |
| --- | --- |
| 单模块 | `lang/zh-CN/<域>/<模块>.json` |
| 模块有子功能 | `lang/zh-CN/<域>/<模块>.<子功能>.json` |
| 域下模块很多 | `lang/zh-CN/<域>/<子域>/<模块>.json` |
| 通用文案 | `locales/langs/<locale>/common.json` |
| 插件文案 | `plugin/<name>/lang/<locale>/*.json` |

## 九、注意事项

| ✅ 推荐 | ❌ 避免 |
| --- | --- |
| 中英文语言包结构对称 | 只加中文，英文缺失 |
| 用 `$t()` 包裹所有展示文案 | 硬编码中文 |
| Key 语义化分层 | 扁平化一堆 key |
| 同模块只用一种文件组织方式 | 混用导致 key 冲突 |
| 插件文案放插件自己的 `lang/` | 塞进主应用语言包 |
| 参数化文案用占位符 | 字符串拼接 |

---

## 十、多套 UI 注意点

国际化模块**完全与 UI 无关**：

| 项 | 换 UI 时 |
| --- | --- |
| `locales/loader/` | ✅ 不改 |
| `locales/langs/` | ✅ 不改 |
| `lang/` | ✅ 不改 |
| `core/locales/` | ✅ 不改 |

唯一相关的是 UI 库自身的语言包（如 Element Plus 的 `zhCn`），需在 UI 库的 ConfigProvider 中配置，属于 `adapter/` 或 `core/ui/` 的工作。
